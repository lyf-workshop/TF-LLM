# 项目当前状态

## 阶段定位

TF-LLM 从 Training-Free GRPO 出发，希望把一次性的经验提取扩展为可评估、可筛选、可持续更新的自进化 Agent。当前仍处于第一阶段：建立可信基线、统一评估协议，并验证最小经验闭环是否真实有效。

## 已经实现

- 统一的 `run_eval.py` 评估入口与 `run_training_free_GRPO.py` 经验学习入口。
- AIME、LiveCodeBench、WebWalkerQA、ZebraLogic、SkillsBench 和三类 KORGym 游戏适配。
- 从多条 rollout 中提取经验并生成经验 Agent。
- L0、L1、L2 分层经验的数据结构、更新和持久化代码。
- 静态、BM25 检索和 LLM rerank 三种经验选择模式。
- SkillsBench 成对调度、基础设施错误分类、无效试次补跑与发布门禁。
- 经验审计、冲突检测和误差分析的辅助实现。

## 已经验证

- 核心环境与 SkillsBench 环境预检可以在 WSL2 中通过。
- SkillsBench 论文 87 任务可展开为每组 261 个试次，并按任务配对运行。
- 网络、429/5xx、Harbor 异常和缺失 reward 文件可与 verifier 失败分开记录。
- 当前 SkillsBench 可靠性与生成 Agent 相关自动化测试通过。

这些结论只说明评估基础设施可运行，不等价于经验方法优于 baseline。

## 尚未验证

- 分层经验是否在独立评估集上稳定提升准确率。
- 经验筛选、删除和质量反馈是否形成真正的自动闭环。
- 跨任务、跨领域经验迁移是否有效。
- 多轮自更新是否持续提升而非累积错误。
- 不同模型、不同 endpoint 下的收益是否可复现。

早期 SkillsBench 探索实验中，经验组通过率低于 baseline。因此当前不能宣称分层经验已经有效，也不能把已有代码称为已经完成的自进化系统。

## 必要对照组

正式实验至少应包含：

1. 无经验 baseline。
2. 原始或扁平 Training-Free GRPO 经验。
3. 当前分层或检索式经验。
4. 等长度无关经验，排除仅因提示词更长造成的变化。

所有组必须固定数据、模型版本、采样参数、超时、工具、verifier 和运行时段。基础设施失败应补跑，不能混入任务失败。

## 下一阶段

1. 在一个低成本数据集上跑通“学习、注入、评估、筛选、再评估”的最小闭环。
2. 先确认相对 baseline 的收益与方差，再扩大到 SkillsBench。
3. 对增益和退化任务做逐例审计，建立经验贡献记录。
4. 只有在多次独立运行中稳定提升后，再加入自动删除、跨任务迁移和多轮自进化。

向导师汇报时，建议将当前工作描述为“多数据集基线与可复现评估平台建设，以及自进化 Agent 的第一阶段验证”，而不是已经完成自进化 Agent。
