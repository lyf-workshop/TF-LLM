# LLM-Based Experience Filtering Guide

## 📖 Overview

This feature enables **intelligent experience selection** using Large Language Models (LLMs) to evaluate and rank hierarchical experiences (L0/L1/L2) based on their relevance to specific tasks.

### Key Benefits

- 🎯 **Task-Aware Selection**: LLM evaluates experiences based on current task context
- 🚀 **Better Performance**: Inject only the most relevant experiences, reducing noise
- ⚡ **Flexible Strategies**: Support static, BM25, and LLM-based filtering
- 📊 **Two-Stage Pipeline**: Efficient recall + intelligent reranking

---

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────┐
│                  Base Agent Prompt                       │
│  (No experiences, pure task instructions)                │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│              Load Experiences from JSON                  │
│  workspace/hierarchical_experiences/wordle_practice_2.json│
│  • L2 (Meta-strategy): 1 experience                      │
│  • L1 (Pattern-level): 4 experiences                     │
│  • L0 (Case-level): 26 experiences                       │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│            Stage 1: Recall Candidates                    │
│  Method: static | bm25 | all                            │
│  • Filter by level limits (max_l2, max_l1, max_l0)     │
│  • Result: 31 → 15-20 candidates                        │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│         Stage 2: LLM Reranking (Optional)               │
│  • Build prompt with task context + experiences          │
│  • LLM evaluates each experience (0-10 score)           │
│  • Sort by score, select top-k (e.g., 8 experiences)    │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│          Inject Selected Experiences into Agent          │
│  Format: "When solving problems, you MUST first..."     │
│  [L2_0]. [L2-Meta] Core meta-strategy...                │
│  [L1_0]. [L1-Pattern] Pattern for opening moves...      │
│  ...                                                     │
└─────────────────────────────────────────────────────────┘
                         ↓
                  Run Evaluation
```

## 🚀 Quick Start

### 0. Configure Environment Variables

Ensure your `.env` file contains the LLM API configuration:

```bash
# Required: API key for LLM reranking
UTU_LLM_API_KEY=sk-your-api-key-here

# Required: Base URL for your LLM provider
UTU_LLM_BASE_URL=https://api.zhizengzeng.com/v1

# Optional: Model to use (default: qwen3-32b)
UTU_LLM_MODEL=qwen3-32b
```

**Note**: The reranker will use `UTU_LLM_API_KEY` (project standard) or fallback to `OPENAI_API_KEY` for compatibility.

### 1. Prepare Experience File

Ensure you have a hierarchical experience JSON file:

```bash
workspace/hierarchical_experiences/wordle_practice_2.json
```

Generated by `hierarchical_experience_manager.py` during training.

### 2. Configure Evaluation

Create or modify your eval config (e.g., `configs/eval/korgym/wordle_eval_llm.yaml`):

```yaml
# Base agent config (no experiences)
defaults:
  - /agents/practice/wordle_agent@agent
  - _self_

exp_id: "wordle_eval_llm"

# Experience filtering with LLM reranking
experience_filter:
  enabled: true
  strategy: "llm_rerank"
  
  # Load experiences from external JSON
  experience_source: "workspace/hierarchical_experiences/wordle_practice_2.json"
  
  # Stage 1: Recall
  recall:
    method: "static"
    max_l2: null  # Include all L2
    max_l1: null  # Include all L1
    max_l0: 30    # Limit L0 to 30
  
  # Stage 2: LLM Rerank
  llm_rerank:
    enabled: true
    model: "qwen3-32b"
    temperature: 0.1
    max_candidates: 20
    final_top_k: 8
    include_reasoning: true
```

### 3. Run Evaluation

```bash
# Test the filtering (without running full eval)
uv run python scripts/test_llm_experience_filter.py

# Run full evaluation
uv run python scripts/run_eval.py --config_name korgym/wordle_eval_llm
```

## 📋 Configuration Options

### Top-Level Settings

| Parameter | Type | Description |
|-----------|------|-------------|
| `enabled` | bool | Enable/disable experience filtering |
| `strategy` | str | Filtering strategy: `"static"`, `"retrieval"`, `"llm_rerank"` |
| `experience_source` | str | Path to hierarchical experience JSON file |

### Recall Configuration (`recall:`)

| Parameter | Type | Description |
|-----------|------|-------------|
| `method` | str | Recall method: `"static"`, `"bm25"`, `"all"` |
| `max_l2` | int\|null | Max L2 experiences to recall (null = all) |
| `max_l1` | int\|null | Max L1 experiences to recall (null = all) |
| `max_l0` | int\|null | Max L0 experiences to recall (null = all) |

### LLM Rerank Configuration (`llm_rerank:`)

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `enabled` | bool | false | Enable LLM reranking |
| `model` | str | "qwen3-32b" | LLM model name |
| `temperature` | float | 0.1 | Sampling temperature (0-1) |
| `max_candidates` | int | 20 | Max experiences to evaluate with LLM |
| `final_top_k` | int | 8 | Final number to inject into agent |
| `include_reasoning` | bool | true | Log LLM reasoning for scores |
| `timeout` | int | 60 | API timeout in seconds |

## 🎯 Usage Scenarios

### Scenario 1: Baseline (Static Filtering)

**Use Case**: Quick evaluation, deterministic results, no LLM cost

```yaml
experience_filter:
  enabled: true
  strategy: "static"
  experience_source: "workspace/hierarchical_experiences/wordle_practice_2.json"
  max_l2: 1
  max_l1: 3
  max_l0: 5
```

**Expected**: Always select first 1 L2, 3 L1, and 5 L0 experiences.

---

### Scenario 2: LLM Reranking (Recommended)

**Use Case**: Best performance, task-aware selection, acceptable cost

```yaml
experience_filter:
  enabled: true
  strategy: "llm_rerank"
  experience_source: "workspace/hierarchical_experiences/wordle_practice_2.json"
  
  recall:
    method: "static"
    max_l2: null
    max_l1: null
    max_l0: 30
  
  llm_rerank:
    enabled: true
    model: "qwen3-32b"
    temperature: 0.1
    max_candidates: 20
    final_top_k: 8
```

**Expected**: 
1. Recall all L2, L1, and top 30 L0 (total ~35)
2. LLM evaluates top 20 candidates
3. Return 8 most relevant experiences

**Cost**: ~1 LLM call per evaluation (reranking is done once at startup)

---

### Scenario 3: Hybrid (BM25 + LLM)

**Use Case**: Large experience pool, semantic retrieval + intelligent ranking

```yaml
experience_filter:
  enabled: true
  strategy: "llm_rerank"
  experience_source: "workspace/hierarchical_experiences/wordle_practice_2.json"
  
  recall:
    method: "bm25"
  
  llm_rerank:
    enabled: true
    max_candidates: 15
    final_top_k: 8
```

**Expected**: BM25 retrieves semantically similar experiences, then LLM reranks them.

---

### Scenario 4: Cost-Optimized

**Use Case**: Minimize LLM API costs while maintaining quality

```yaml
experience_filter:
  enabled: true
  strategy: "llm_rerank"
  experience_source: "workspace/hierarchical_experiences/wordle_practice_2.json"
  
  recall:
    method: "static"
    max_l2: 1
    max_l1: 5
    max_l0: 10  # Aggressive filtering
  
  llm_rerank:
    enabled: true
    max_candidates: 10  # Fewer candidates
    final_top_k: 5      # Fewer final experiences
    temperature: 0.0    # Deterministic
```

## 🔧 Troubleshooting

### Issue 1: "API key not found"

**Error**: `ValueError: Environment variable OPENAI_API_KEY is not set`

**Fix**: Add API key to your `.env` file:
```bash
# Use project standard variable
UTU_LLM_API_KEY=sk-your-api-key-here
UTU_LLM_BASE_URL=https://api.zhizengzeng.com/v1

# OR use standard OpenAI variable
OPENAI_API_KEY=sk-your-api-key-here
OPENAI_BASE_URL=https://api.openai.com/v1
```

Then restart your script.

---

### Issue 2: "Experience file not found"

**Error**: `FileNotFoundError: workspace/hierarchical_experiences/wordle_practice_2.json`

**Fix**: Ensure experience file exists. Generate it by running training:
```bash
uv run python scripts/run_training_free_GRPO.py --config_name korgym/wordle_practice
```

---

### Issue 3: LLM API Timeout

**Error**: `asyncio.TimeoutError: LLM API call timed out after 60s`

**Fix**: Increase timeout in config:
```yaml
llm_rerank:
  timeout: 120  # Increase to 120s
```

---

### Issue 4: Low-Quality Scores

**Symptom**: All experiences get similar scores (e.g., 5.0-6.0)

**Possible Causes**:
- Task context is too generic
- LLM model is not suitable
- Temperature too high

**Fix**:
```yaml
llm_rerank:
  temperature: 0.0  # More deterministic
  model: "gpt-4"    # Try different model
```

Improve task context in `base_benchmark.py::_get_task_context()`.

---

### Issue 5: "No experiences injected"

**Symptom**: Final instructions don't contain experience section

**Debug**:
```python
# Check if experiences were loaded
filter = ExperienceFilter(config)
experiences = filter.load_experiences_from_source()
print(f"Loaded: {len(experiences)} experiences")

# Check filtering result
filtered = await filter.filter_experiences(experiences, query="...")
print(f"Filtered: {len(filtered)} experiences")
```

## 📚 Implementation Details

### LLM Prompt Template

The reranker uses the following prompt structure:

```
SYSTEM:
You are an AI experience relevance evaluator for a game-playing agent.
Evaluate each experience based on:
1. Relevance (0-4): How directly applicable to current task
2. Generalization (0-3): Broad vs overly specific
3. Actionability (0-3): Direct usability

Output strict JSON array with scores 0-10.

USER:
**Current Task Context**:
Wordle game: Guess a 4-letter hidden word within 10 attempts...

**Candidate Experiences** (20 total):
1. **[L2_0]** (L2)
   [L2-Meta] Principle: Iteratively maximize information gain...

2. **[L1_0]** (L1)
   [L1-Pattern] Maximize information gain through strategic initial guesses...

...

Evaluate each experience and return the JSON array with scores.
```

### Caching

The reranker caches results based on `(task_context, experience_ids)` hash:
- Same task + same experiences = cached result
- Reduces redundant LLM calls
- Cache is in-memory (cleared on restart)

## 🎓 Best Practices

### 1. Start with Static Filtering

Establish a baseline before enabling LLM reranking:

```yaml
# Step 1: Static baseline
experience_filter:
  strategy: "static"
  max_l2: 1
  max_l1: 3
  max_l0: 5

# Step 2: Enable LLM
experience_filter:
  strategy: "llm_rerank"
  # ... compare results
```

### 2. Tune Recall Stage First

Recall is fast and cheap. Find a good recall configuration:

```yaml
recall:
  method: "static"
  max_l0: 50  # Too many? → Try 30
```

### 3. Monitor LLM Costs

Each evaluation run calls LLM once for reranking:
- Cost: ~$0.01 per call (model-dependent)
- For 50 samples: ~$0.50 total

### 4. Adjust `final_top_k` Based on Context Window

- Short context models: `final_top_k: 5`
- Large context models: `final_top_k: 10-15`

### 5. Use `include_reasoning: true` for Debugging

Enable to see why LLM scored each experience:

```
[L2_0] score=9.2: Core meta-strategy directly applicable
[L1_3] score=7.5: Useful pattern but somewhat generic
[L0_8] score=4.2: Too specific to 5-letter words
```
