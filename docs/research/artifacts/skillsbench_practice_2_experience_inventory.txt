--------------------------------------------------------------------------------
【L2 元策略 (Meta-strategy)】
--------------------------------------------------------------------------------

[L2-1] 系统化分解与验证 (Systematic decomposition and verification)
  将模糊任务转化为线性、带门控的小阶段序列，每个阶段都有前置条件和可验证的
  输出。嵌入分层验证：先做轻量的环境/结构检查，再将关键输出与权威 ground truth
  交叉验证。从一个最小的端到端切片开始验证假设，然后带验证地迭代扩展。用自动化
  检查、明确的回退计划和恢复策略来隔离失败，保证可控的增量推进和可审计的执行。


--------------------------------------------------------------------------------
【L1 模式级 (Pattern-level)】
--------------------------------------------------------------------------------

[L1-1] 约束驱动的验证优先工作流
  尽早选择可靠工具，按正确 schema 增量构建输出，把每条显式约束提取成在合适
  流水线阶段执行的验证步骤，集成组件前持续校验中间/最终结果是否符合格式与内容要求。

[L1-2] 分解为可重复的小流水线
  diagnose → 定位相关代码/配置 → 在隔离模块中实现改动 → apply/build/run →
  用针对性工具验证；尽早用快速诊断命令和搜索/导航工具指导每一步，推进前先验证进展。

[L1-3] 分解为清晰的顺序阶段
  inspect/validate 输入 → transform/aggregate → apply changes → test outputs；
  每个阶段主动验证数据结构/schema 和可访问性，用健壮工具（如 awk 关联数组）并记录
  中间结果以尽早发现错误、保证可追溯。

[L1-4] 主动建立干净、可理解的执行上下文
  检测环境/OS、强制确定性的资源命名、清理历史产物，然后以模块化阶段执行，
  每步做显式的领域建模与验证，预防冲突、尽早发现错误。

[L1-5] 预检验证与增量验证
  改动前先检查当前环境/资源（文件、权限、运行中的服务）并主动解决冲突，然后
  分阶段执行，每步后用自动化、可脚本化的检查尽早捕获错误和约束违规。

[L1-6] 带检查点的分阶段执行
  先验证前置条件、检查输入，再把任务分解成带保存检查点的清晰阶段，并设置
  带超时的回退路径，确保操作失败时仍能向前推进。

[L1-7] 小而可验证的阶段 + 预检
  把工作流分解为小而可验证的阶段，每个阶段执行前对环境状态和依赖做预检
  （含清理/幂等资源处理），从而尽早隔离失败，并通过确定性清理或回退路径恢复，
  避免单个被阻塞的依赖拖垮整个任务。

[L1-8] 依赖预检验证
  执行前验证所有外部依赖（容器、软件包、环境变量、服务、连通性），嵌入
  回退/清理逻辑以处理冲突或瞬时错误，然后以小而可测试的阶段推进。

[L1-9] 弹性模块化工作流
  采用模块化、依赖感知的工作流，把任务拆成独立阶段，预校验资源，默认使用
  轻量本地工具或并行处理，隔离依赖以在服务不可靠时维持进展，并保留清晰日志便于调试。

[L1-10] 带日志与回退的健壮脚本
  映射输入、缓存重复观测、使用隔离环境和模块化设计并记录日志以提高可观测性，
  应用系统化的回退检查，根据需求校验输出而非盲目相信退出码。

[L1-11] 验证优先的迭代循环
  本地原型、检查输入、自动化执行同时记录指标和断言，用可度量的结果迭代优化
  直到满足规格要求。

[L1-12] 最小端到端切片
  从一个最小可用的端到端切片开始，尽早验证工具链、数据和预期输出，然后增量
  扩展，同时加固输入边界并用显式断言校验中间结果。

[L1-13] 分层验证工作流
  处理前先审计环境和约束；先用最小、健壮的工具执行，仅在必要时升级到更重的方法，
  同时持续检查输出以确保正确性。

[L1-14] 一手来源的 ground-truth 锚定
  从原始数据生成结构化输出后，通过扫描原始输入结构、逆向内部参数或穷举记录候选
  极值来提取 ground truth，再把关键值与该独立基线交叉核对，捕获格式校验器发现不了的
  语义错误和系统性处理缺陷。

[L1-15] 基于清单的产物完整性校验
  生成包含相互依赖部分的输出（图、电子表格、解析数据）时，运行一个程序化清单做
  跨组件完整性检查（连通性、字段对齐、公式准确性），并在最终确定前修复失败项。


--------------------------------------------------------------------------------
【L0 案例级 (Case-level)】
--------------------------------------------------------------------------------

[L0-1] 借助 skill 工具的数据驱动规划
  映射环境（列出 skills、读 SKILL.md、检查 schema），分解成简单的已验证查询。
  用 Python 脚本（heredoc）避免引号错误；打印并验证每个结果（行数、列）。组装输出
  并用断言工具校验 schema 与约束。

[L0-2] Suricata 签名的门控循环
  用 tshark 捕获所需流量组件的精确字节序列，增量构建规则，每加一个条件就用
  正/负 pcap 通过 suricata -T 和回放验证，每次测试后检查日志。只在指定 SID 下合并成
  最终规则并保存检查点日志，避免误判验证。

[L0-3] 论文复现的诊断序列
  从带 repo 的论文复现代码时，实现前先执行 cd <repo>、ls -R、cat trainer 文件、
  cat 单元测试、记录环境（python -VV, pip freeze），用接口、shape 和参考实现给 agent 打底。

[L0-4] 带修复的启动策略
  任务开始时强制做预检（验证工作目录、文件、运行时、库、代码/文档、输入内容）。
  任何检查失败就捕获错误、报告、尝试简单修复（重装包、重启 runner）再继续。然后
  分解成带成功标准和时间预算的子任务，产出可观测产物并做就绪检查。

[L0-5] TTS 的可靠文本提取
  一次失败后就放弃脆弱的正则 HTML 提取；改用成熟工具（lynx、html2text、
  BeautifulSoup.get_text()）获取干净纯文本，再通过检查开头/结尾句和字数来验证。

[L0-6] 带章节检测的媒体文件审计
  媒体提取任务先用零依赖的 ffprobe -show_chapters 快速审计；无元数据则用更重的工具
  分层回退；始终产出尽力而为的输出。

[L0-7] 显式工具约束的遵守与验证
  始终遵守任务的显式工具约束，可证明地使用该工具的核心功能（不止 import），
  与独立方法交叉验证结果以捕获错误，并在宣布完成前尽早写出/检查输出。

[L0-8] Python 脚本持久化
  多行 Python 代码用健壮的文件写入方式（多行 echo 或 tee），始终验证文件写对
  （wc -l），避免可能截断的脆弱 heredoc；若用 heredoc 务必正确引用以避免转义问题。

[L0-9] TTS 库版本处理
  安装前固定关键库版本，做 import 测试，不匹配就重装或调整用法；必要时回退到离线引擎。

[L0-10] TTS 多后端健康检查
  设计 TTS 配音流水线时配一个健康检查脚本测试多个后端；核心逻辑选第一个可用后端，
  避免单一依赖导致整体失败。

[L0-11] 端到端脚本承诺
  对有相互依赖约束的结构化数据组装任务，初步调研工具和 schema 后，构建单个完整脚本
  顺序查询所有所需来源、应用过滤、聚合并写出输出，防止无尽探索并保证端到端约束验证。

[L0-12] 逐步调试科学库
  调试不熟悉的科学库时，捕获完整错误输出，用 help() 或 inspect.getsource() 验证预期
  输入，隔离测试每个流水线组件并打印中间值，环境无响应时带日志中止，避免盲目重试。

[L0-13] 文档优先策略
  外部查询前先穷尽本地 skill 文档（SKILL.md、README）和规定的工作流，最小化 API
  调用、避免猜测。

[L0-14] 跨表键匹配
  写跨表查找公式前，从两个范围提取并比较查找键；若格式不同则调整公式（如通配符），
  避免静默的 #N/A 错误。

[L0-15] 带时间预算的 Excel 分解
  把 Excel+外部数据任务分解为模板映射、数据收集/验证（每来源限时）、纯公式填充、
  最终 Excel 步骤，防止过度投入。

[L0-16] 配置-执行的验证门
  把环境配置与任务执行用验证门分开；门失败则自动调用文档化的回退方案，保持重依赖
  任务的弹性。

[L0-17] 环境引导与验证门控
  任何任务前强制做环境引导：列出工作区、读所有相关源文件、验证工具可用；然后定位
  所需规格、验证完整性、表述分步计划，再开始实现。

[L0-18] 带分块的 TTS 回退
  云 TTS API 不可用时切换到 edge-tts，移除所有云 API 引用，把长文本按句/段拆分，
  按块生成音频（带逐块超时/重试），用 ffmpeg 拼接，每阶段做显式存在/大小检查。

[L0-19] 强制工具遵守 + 有界探索
  把显式要求的工具视为强制；不可用就报告并请求指导而非静默切换。简短检查目标文件后，
  立即用可用数据开始写数据/公式，防止分析瘫痪和超时。

[L0-20] 截止驱动的部分输出
  对限时任务，初步检查文件后分解成增量流水线、频繁写部分结果；设内部截止闹钟触发
  简化回退（如默认 UNKNOWN），保证至少有符合 schema 的部分输出、防止超时。

[L0-21] 目标导向的表单填写 (Explore→Map→Fill→Verify)
  快速检查表单字段和类型；建立所需数据与控件名的映射；主库无法设置所有字段类型
  （如复选框）就回退到 PyMuPDF 直接操作控件；保存并重读每个填入值验证。避免无方向的
  布局探索，每个字段都对照任务描述核对。

[L0-22] 内容存在性的图验证
  从原始文本生成图后，用 grep 模式提取预期节点 ID 和边目标，然后断言每个提取元素都
  出现在输出中，捕获缺失或误解析的组件。

[L0-23] 带验证的数据比对流水线
  对涉及非结构化来源的数据比对任务，先检查原始数据理解布局，再提取成归一化的键索引
  结构，通过集合运算和逐字段检查计算 delta，用针对性抽查和自动断言（排序、类型、无重复）
  校验输出。

[L0-24] diff 后的内容验证
  生成 diff/比对输出后，程序化验证正确性：确认被删记录不在新来源中，抽查几个被修改
  字段对照原始数据，捕获超出语法有效性的逻辑错误。

[L0-25] 漏洞报告验证
  运行专门验证脚本检查：表头符合要求、所有 CVE 都在、severity 严格为 'HIGH' 或
  'CRITICAL'、CVSS_Score 可解析或为 N/A、无修复时 Fixed_Version 为 N/A、行数与扫描器
  汇总一致、Url 非空，并抽查一个 CVE 对照 NVD。

[L0-26] 构建后 Excel 结构验证
  构建 Excel 报告后，运行独立验证脚本检查每条显式要求：sheet 名精确匹配、透视
  行/列/值字段正确、数值合计与源数据对账、派生列（如四分位分箱）正确覆盖所有记录。
  此步非可选。

[L0-27] 按内容用关键词字典组织文件
  盘点所有文件，按扩展名构建可扩展的提取函数到稳定中间文件；从小样本设计关键词/主题
  分类字典；在全量数据上应用规则（不重新提取）；程序化移动文件；通过对比最终文件夹
  计数与原始总数并按类抽查来验证完整性。

[L0-28] 图生成后验证
  生成图（如从文本生成 DOT）后做检查：(1) 节点完整性：无重复节点 ID、必需字段齐全
  (id, text, speaker, type)；(2) 边目标存在性：确认每条边的目标节点存在（处理终端节点）；
  (3) 可达性：从起始节点 BFS/DFS 标记不可达节点。最终输出前修复问题。

[L0-29] 模板映射验证
  把结构化输入数据映射到模板（PDF 表单、配置文件、HTML）时，程序化加载输出并用显式
  清单核对每个必需数据项；用最小示例测试 UI 特定值格式（复选框、日期选择器），可选地
  用另一工具交叉验证以捕获库特有的怪异行为。

[L0-30] 两阶段写入前验证
  插入跨表查找和分组统计公式前，做键匹配（比较精确字符串）和分组标签提取以确保公式准确。

[L0-31] 动态的基于分组的公式构建
  程序化读取分组分配标签（如一行组名）并构建引用这些标签的统计公式（AVERAGEIF、
  STDEV.S），绝不假设固定列序。

[L0-32] 带回退的多源 CVSS 提取
  解析扫描器 JSON（如 Trivy）时，从 NVD、GHSA、RedHat 中第一个可用权威源提取 CVSS
  分数（优先 NVD），回退到 0.0。缺失的修复版本默认 'N/A'。开发时打印样本确认字段映射。

[L0-33] 内部一致性交叉验证
  从源数据生成输出后，程序化加载二者并断言键/匹配的集合一致、无空行、派生分布与源
  匹配。尽早捕获不匹配，普遍适用。

[L0-34] 多源组装的约束验证
  从多来源组装数据驱动输出时，在检索时或检索后用过滤器显式程序化验证每条用户约束
  （如预算、菜系、宠物友好），再生成最终产物。

[L0-35] 约束优先的工具映射
  给定严格的工具/格式约束时，首个动作就是提取约束、把每个所需操作映射到允许的工具、
  尝试安装强制工具、不行就记录偏差并回退到允许的原生方法，每个子任务后含验证检查点。

[L0-36] 解析器预扫描与分层验证
  构建结构化文本到图的解析器时，先用 grep/sed 穷尽扫描输入的所有结构标记，生成后通过
  确保每个语法实体都有节点/边、强制领域约束（可达性）、检查输出语法来验证。

[L0-37] 模拟器内部逆向工程
  当模拟器源码暴露内部参数生成时，提取真实参数（如 seed 和哈希逻辑）获取 ground truth；
  用它们验证实验校准并指导控制器设计，减少对噪声测量的依赖。

[L0-38] 权威几何与投影
  空间距离任务始终使用最权威、最完整的边界几何（如 polygon 文件）并应用规定的投影
  方法；不要从不完整来源拼凑。

[L0-39] 极值候选记录
  最大/最小任务始终计算并记录所有相关候选的指标，打印 top-N 值和标识符，以便下结论前
  做合理性检查。

[L0-40] 极值 top 验证
  记录所有候选后，用独立的粗略估算（如测地线计算器）验证选中的 top 候选，以检测系统性
  错误。
