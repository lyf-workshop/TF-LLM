# 分层经验机制

## 三个层级

| 层级 | 含义 | 来源 | 例子 |
| --- | --- | --- | --- |
| L0 | 单任务、案例级经验 | 每一步的新轨迹洞见 | 某类输入的具体错误与修正 |
| L1 | 可复用模式 | 每个 epoch 从新增 L0 聚合 | 一类任务通用的操作顺序 |
| L2 | 元策略 | 每个 epoch 从当前 L1 聚合 | 验证、回退与资源管理原则 |

`HierarchicalExperienceManager` 在每个 step 合并 L0，在 epoch 结束时执行 L0 到 L1、L1 到 L2 的聚合。三个池共用语义合并操作：`ADD`、`UPDATE`、`DELETE` 和 `NONE`。

## 数据流

```text
轨迹对比 -> 原始洞见 -> L0 池
                         |
                         v
                    新增 L0 聚合 -> L1 池
                                      |
                                      v
                                 L1 聚合 -> L2 池
```

经验 JSON 通常位于 `workspace/hierarchical_experiences/`。生成的 Agent YAML 位于 `configs/agents/practice/`，将选定经验写入 instructions。

## 关键配置

practice YAML 的 `hierarchical_learning` 控制是否启用、L1/L2 聚合阈值、最近 L0 注入数量以及保存路径。阈值不足时对应层级会跳过聚合，这不是运行错误。

## 研究风险

- 更抽象不代表更正确，L1/L2 可能放大早期错误。
- 语义合并由 LLM 决定，存在随机性和错误删除风险。
- 注入更多经验可能增加上下文干扰或掩盖原始任务指令。
- 同一经验对不同任务可能产生相反作用。

因此必须保留平坦经验对照、经验数量控制和任务级增益/退化记录。当前实现具备分层更新能力，但“分层优于平坦”的结论仍待实验验证。
