# TF-LLM 项目阶段说明

## 当前阶段

本项目基于 Training-Free GRPO，目前处于基线复现、评测环境建设和主数据集筛选阶段，
尚未实现经过实验验证的 Agent 自进化闭环。现阶段接入多个数据集的目的，是建立可靠的
对照实验流程，并比较不同任务的奖励稳定性、运行成本、基础设施可靠性和经验迁移空间。

当前已接入或准备了 KORGym、ZebraLogic、LiveCodeBench、SkillsBench、数学和网页任务。
后续将从中确定一个快速稳定的主开发集，以及一个用于检验跨任务泛化的外部验证集。

## 研究目标

计划研究一种不更新模型参数、由外部经验记忆驱动的自进化 Agent。目标闭环为：

1. 针对任务生成多条候选轨迹。
2. 从成功和失败轨迹中提取可复用经验。
3. 将筛选后的经验用于后续任务。
4. 与相同条件下的无经验组比较，测量经验的真实作用。
5. 根据观测结果保留、修正或删除经验，再进入下一轮任务。

在最小的扁平经验闭环得到验证之后，再研究 L0/L1/L2 分层经验、按任务检索和基于效果的
经验淘汰。这样可以逐步区分各模块的独立贡献，避免一次加入过多机制后无法归因。

## 需要建立的基线

- 不使用经验的基础 Agent。
- 原始 Training-Free GRPO 扁平经验方法。
- 注入等长度普通说明的提示词长度对照。
- 注入无关经验的负迁移对照。
- 完成上述基线后再加入本项目的闭环方法。

所有组应固定模型版本、API endpoint、temperature、任务集合、超时策略和 verifier。
网络、Docker 或评估框架故障应标记为基础设施无效试次，不能计为 Agent 失败。

## 当前仓库瘦身原则

面向导师同步的分支保留研究代码、可复现实验配置、测试和少量代表性产物；不跟踪本地
虚拟环境、数据库、外部 benchmark 检出目录、Harbor 兼容缓存、临时输出、密钥文件和
KORGym 上游附带的大型历史评测结果。

历史脚本、重复配置、归档文档和自动生成的 Agent 暂时保留。等主开发数据集和唯一标准
实验入口确定后，再进行第二轮结构清理，避免过早删除仍可能用于基线复现的内容。
